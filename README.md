# 需求訪談訪綱產生器（requirement-interview-guide）

把果思過去 28 個專案的需訪經驗，組裝成「輸入專案資料 → 場次規劃 → 逐場訪綱」的產生流程。目標：讓非研究員也能快速產出一份**可靠的起頭版本**——縮減不確定範圍、聚焦出可能還需調整的地方，讓後續與專案成員或 mentor 的討論更有效率（產出仍需經內部確認後才送客戶窗口）。

- 版本：v0.9.1（2026-07-23）｜維護者：佳紜（Goons Design）
- 狀態：實測調校中，**尚未正式安裝到 Claude app 的自訂功能**——目前一律採「手動載入」方式使用（見下方兩種情境）。

---

## 一、這個工具做什麼

輸入專案資料（最推薦：Notion 專案頁連結，可自動判讀），經過兩個確認關卡（定位判讀 → 場次規劃），逐場產出訪綱，確認後寫回 Notion 專案頁，並產出兩份紀錄檔。

產出物清單：

1. **場次規劃表**（先確認再產綱）
2. **各場訪綱**（一場一份 md；標題格式「{部門或對象}｜{專案名稱}｜需求訪談訪綱」）
3. **給主訪的備註**（執行提醒集中檔，不進訪綱本體）
4. **訪綱決策紀錄**（8 節；給不在專案內的 mentor／管理者 快速進入狀況、聚焦給意見）
5. **skill 使用 log**（即時追加式事件流水帳，交給 skill 維護者分析規則缺口）
6. **Notion 寫回**（可選）：專案頁「三、專案階段文件 > 1. PM」下建目錄頁，內含場次規劃表＋備註頁＋各場訪綱頁＋決策紀錄頁

## 二、怎麼使用（兩種情境）

### 情境 A｜Claude app（chat 或 Cowork 任務）

尚未安裝進 app 自訂功能前，採「附檔載入」：

1. 取得本資料夾（`requirement-interview-guide/`，含 SKILL.md 與 references/）或其 zip。
2. 開新對話或 Cowork 任務：
   - **Cowork**：連接含本資料夾的資料夾（或直接把 zip 拖進對話）。
   - **chat**：把 zip 或整個資料夾的檔案上傳到對話。
3. 貼觸發語（見下方），並加一句：「**請依附件中 SKILL.md 的流程執行**」。
4. 要用 Notion 自動判讀與寫回，需該對話已連接 Notion 連接器；沒有連接器時工具會退回手動問答模式，一樣能產訪綱。

### 情境 B｜本機端（Claude Code）

1. 把本資料夾放到專案的 `.claude/skills/requirement-interview-guide/`（僅該專案可用），或 `~/.claude/skills/requirement-interview-guide/`（該機器全域可用）。
2. 在 Claude Code 對話中輸入 `/requirement-interview-guide`，或直接說觸發語——skill 會被自動載入。
3. Notion 串接同樣依該環境是否配置了 Notion MCP 而定。

### 之後的正式安裝（升級路徑）

等測試修到穩定版本後，再把 zip 安裝到 Claude app 的自訂功能（skills）中，屆時全公司帳號開對話即可直接觸發、不需附檔。**在那之前請都用上面 A／B 的手動方式**，並把使用過程的 log 回傳給維護者。

## 三、觸發語

以下任何說法都應觸發（脈絡是專案前期的客戶端訪談即可）：

> 「我要幫新專案產需求訪談訪綱：{Notion 專案頁連結}」
> 「幫我排 ○○ 案的訪談場次」「這個案子要訪哪些人？」
> 「幫我準備下週跟客戶的需求訪談」「產利關人訪談訪綱」

**不適用**：對外部消費者的用戶訪談、易用性測試、售前提案期洽談。

## 四、輸入需求

| 項目 | 必／選 | 說明 |
|---|---|---|
| 專案基本資料 | 必 | 最推薦給 Notion 專案頁連結（自動判讀）；否則手動提供客戶、產業、SOW 摘要、時程 |
| 專案性質定位判斷所需資訊 | 必 | 用來判斷「這是哪種案型」的兩件事：產品主要給誰用（公司內部人員／外部市場客群）、這次是優化既有產品還是從零建置——工具會自行判讀後跟你確認，不確定就照實說 |
| 利關人結構＋執掌 | 必 | 部門清單與執掌說明；有無關鍵決策者、高層時間 |
| 場次約束 | 選 | 客戶已排定的場次／順序；你自己的拆場想法 |
| 開放題 | 必 | 「這個專案有哪些需要特別注意的地方或風險？」 |
| 走查觀察、必問清單 | 選 | 必問題可給具體題目，**也可以直接指定過去某個專案**請工具加強參考權重 |

## 五、使用注意

- 兩個確認關卡（定位判讀、場次規劃）不會跳過——判讀錯後面全部白做。
- 題量超過時長時工具**自動刪減**並在附註列出被刪題，不會叫你自己刪。
- 決策者統整場的訪綱要等前面場次訪畢、彙整後再回來產（提供各場結論摘要即可）。
- 用完請把「skill 使用 log」檔案交給維護者——這是工具持續改版的原始依據。

```
    ├── 04_特殊場次題組.md        ← 訪前訪／定調場／統整場

```
