# 06｜場次規劃與產綱規則（摘自模板規格 v2，已併入 v3 修訂）

## 一、輸入清單

| 輸入項 | 必／選 | 內容 |
|---|---|---|
| 專案基本資料 | 必 | 客戶名稱、產業、專案範圍（SOW 摘要）、時程 |
| 定位三問 | 必 | ①主要給誰用？（對內營運／對外市場）②改既有或從零做／翻新？（優化／建置）③品牌形象模組判斷（見 02 加掛判斷——由前期資料判斷品牌是否為本案重要議題，不只看使用者勾選） |
| 利關人結構＋部門執掌 | 必 | 涉及部門清單（部門名＋角色＋與專案的關係）＋執掌說明（有執掌資料則訪綱更精準）；有無單一關鍵決策者、高層時間可得性。**交接資料、業務筆記中出現的人名不得直接推定其專案角色**——每人標注角色資訊來源（客戶明載／業務交接／推測），標為「推測」者一律列入判讀確認清單向使用者核對（與「業務診斷觀點需標注來源」為同一資料紀律，適用對象由觀點擴及人名）|
| 既有場次安排 | 選 | 客戶是否已排定場次（共幾場、各場與會者、順序、時長）；使用者自己的拆場想法（想合併誰、場數上限） |
| 開放題 | 必 | 「這個專案有哪些需要特別注意的地方或風險？」 |
| 業務前期筆記／會議紀錄 | 選 | 認知對焦段素材；沒有時對焦段改開放式提問 |
| 設計師走查觀察／商店評價 | 選 | As-is 證據型題目與客服條件題素材 |
| 必問／必保留清單 | 選 | 具體題目 → 併入對應段落、標記必問；**指定過去某專案** → 取該案訪綱與題型加強參考權重 |

## 一之一、源文件完整性關卡（定位判讀前）

- **關鍵源文件先確認「讀到的是原檔還是摘要」**：SOW／合約／計畫書等關鍵源文件，須確認「已實際讀取原檔」或「僅讀到摘要」。僅有摘要時：定位判讀照常進行，但判讀彙整**必須標注「本次判讀依據＝Notion 摘要，未讀原檔」**，並詢問使用者是否提供原檔後再定案。
- **Google Drive 讀取指引**：資料夾連結因連接帳號權限問題幾乎必然失敗（parentId 查詢為空），不重試超過一次；直接請使用者**以單檔共享**方式提供（此為唯一穩定路徑）。

## 二、場次規劃規則

### 2-0 前置判斷（依序）

1. **客戶已有場次安排** → 先分辨是哪一種（不確定時直接問使用者）：
   - **完整安排**（客戶已定案所有要訪的場次）→ 不重排。依既定場次做場次×模組對應、產各場訪綱；發現明顯問題（單場塞太多部門、時長與對象不匹配）或有利關人未被涵蓋時，以「建議語氣」指出，不硬產額外訪綱。
   - **部分安排**（客戶只先定了某些場次的時間或順序，例：總經理場排第一場）→ 已定的部分視為固定約束（順序與時間不動、內容依其位置調整，如決策者在前→定調題）；**其餘利關人場次照 2-1 規則正常規劃並產出訪綱**，與既定場次合併為完整的場次規劃表。
2. **使用者自己有拆場想法** → 以其為基底，只補完（場次目的與順序建議）。
3. **兩者皆無** → 依 2-1 產生建議。

### 2-1 拆場建議規則

**主需求單位判定（前置）**：主需求單位＝專案對接窗口所屬單位，以「誰是果思的主要對口、負責統整需求」判定，**不以話語權高低判定**。話語權最高者若非窗口，僅影響決策者場的配置（定調場／統整場），不改變主需求單位場的內容主體。主需求單位窗口場的中段主體＝主象限模組（窗口為非一手使用者時採觀察／回饋視角），系統限制等附加模組只能作為該場後段，不得反客為主。

- **總場數預設上限 5 場**。超過需同時滿足：時程充裕＋有強需求獨立拆場，否則優先給合併方案。
- 部門 ≤ 2 且有單一決策核心 → 1–2 場；小型案可與 Kickoff 合併單場，或多單位合訪一場。
- 部門 ≥ 3 → 按部門（群）拆場，**優先評估合併**：部門或 title 多、但每部門實際 1–3 人的小團隊，將業務領域相近者併同場（可併 3 個以上單位）；業務關聯高、立場相近者才合併。
- **併場參與度檢核**（合併方案定案前）：**每一與會單位在該場的題量占比不得低於 1/4**（含該單位主答的分流題）。低於門檻時擇一處理：①補足該單位客製題組；②改為不併、獨立成場（總場數因此超過上限 5 時允許例外，於規劃表注明理由）。禁止為守總場數上限而讓某單位大半時間旁聽。
- **有單一關鍵決策者** → 配置決策者場：預設**壓軸統整場**（前場蒐集、最後拿彙整結論驗證＋排序）；決策者時間只約得到前面時改**前置定調場**（先定目標與優先序，後續在此框架內蒐集）。
- **決策權按議題分屬不同人時**（例：視覺定調＝總經理、營運與內容決策＝行銷協理）→ 不強套「單一決策者」規則。每位決策者按其議題配置對應的定調／統整安排：可為獨立場（議題足量時），或於其所在部門場**前段**集中該議題的目標與排序題（議題量少時）。場次規劃表須標注「本場含 {議題} 決策題組（決策者：某某）」，供使用者確認決策題的落點。
- **部門 ≥ 5** → 主動建議加「訪前訪」1 場（主需求單位窗口，60 min），選配。
- 對外 × 建置（研究案起手）適用同一套規則；拆場邏輯傾向按決策層級。

### 2-2 場次順序（建議性質）

主需求單位／窗口先行 → 各部門場 → IT／系統場（收攏技術疑問）→ 決策者統整場壓軸。客戶已排定順序時不重排，僅依順序調整各場內容（決策者場在前→放定調題而非驗證題）。順序影響三件事：驗證題位置、前情提要可用性、限制場收攏功能。

### 2-3 場次時長

- 預設 60 分鐘、上限 90 分鐘（話語權高或資訊密度高的部門給 90；兩部門合併場用 90）。
- **時長看「資訊是否一手」，主需求單位場不自動給 90**：受訪者是天天實際使用／執行的人（一手資訊）→ 密度高、可給 90；受訪者是管理窗口、資訊多為觀察與轉述（二手）→ 60 起跳，僅當該場同時要收策略、制度等額外議題才延長。
- **僅當輸入明確載明可達 120 分鐘時才產 120 分鐘版本。**

## 三、場次 × 模組分配矩陣（多場次案，每題只出現在一場）

| 場次類型 | 中段內容 | 不放的題 |
|---|---|---|
| 訪前訪（選配） | 04 訪前訪題組 | 細節功能題 |
| 定調場（決策者在前） | 04 定調場題組＋品牌模組（若加掛） | As-is 操作細節、規格題 |
| 主需求單位場（一手使用者型：受訪者自己天天用／執行） | 主象限模組全套＋背景確認段完整版 | — |
| 主需求單位場（窗口型：受訪者管理產品、彙整需求，非一手使用者） | 主象限模組**改寫為觀察與回饋視角**（觀察到使用者怎麼用、最常聽到哪些回饋、回饋從哪些管道進來）＋背景確認段完整版 | 任務層與操作走查題（移交一手使用者的場次或後續用戶訪談）；時長依 2-3 下修 |
| 部門蒐集場（行銷／客服／營運／第一線人員） | 03 該部門客製題組＋主象限模組分流給該部門的題 | 其他部門職掌題 |
| IT／系統場 | 02 系統限制釐清模組＋03 IT 客製題 | 品牌、願景題 |
| 決策者統整場（決策者在後） | 04 統整場題組（前場彙整後才產出） | 開放式蒐集題 |

分配原則：品牌題進定調／高層／行銷場；限制題集中 IT 場；排序題放各場結尾或統整場；設計規範確認固定模組分給主需求單位場或設計對接窗口場；刻意的多方視角核對題需標註「多方核對」。

**主需求單位窗口場的主體不被附加模組稀釋**：窗口為非一手使用者時，中段主體仍是主象限模組（改寫為觀察／回饋視角），系統限制等附加模組只能作為該場後段，不得反客為主（例：勿因窗口所屬單位偏系統面，就把整場做成系統限制為主）。

**段落排序規則（原則 16）**：每場訪綱的段落，依思維層次分群排列——思考／策略／觀察類主題相鄰、排在前面；日常操作、行為描述、具體規範限制類排在後面。必要時可合併段落、或把特定題目併到其他段落，避免受訪者反覆切換思考模式。**具體層次由大到小**：目標客群／定位層 → 策略層 → 做法與經營現況層 → 期待與排序；層次高的段落（客群、定位）置於依賴它的段落（新舊客策略、行銷做法）之前。

**合併場（多單位／多受訪者同場）的額外規則**：
- 每段（必要時逐題）標注「本段主要請 {對象} 回答」，讓主訪能快速點名、避免全員輪答每一題。
- 若有主管或高階角色只能出席前段，將其相關題（目標、策略、指標類）集中排在場次前段，優先問完。
- 題量依 05 的合併場折減規則下修。

背景確認段分流：只有目標理解核對題每場必問（可簡短版）；整體計畫關係題放高階決策層級場或主需求單位場（**其中「本案是否屬更大計畫」題收緊為僅高層場**，見 01 該題註記）；特殊狀況題分給主需求單位＋受影響部門場。

## 四、開放題 →「給主訪的備註」轉換

| 輸入類型（範例） | 動作 |
|---|---|
| 「高層很難約」 | 場次規劃建議合併場或訪前資料蒐集；決策者場改 45 min 精簡版 |
| 「某部門對改版有顧慮」 | 該部門場開場加緩和說明；相關題目改中性問法（問現況與期待，不問對改版的態度） |
| 「客戶與前廠商合作不愉快」 | 認知對焦段加「過往合作經驗與在意事項」題 |
| 「有法規敏感議題」 | 掛系統限制釐清模組，限制段加該議題專題 |
| 無法歸類者 | 原文列入「給主訪的備註」（不進訪綱本體） |

## 五、產出物與品質標準

**產出物 A｜場次規劃表**（先確認再產訪綱）：場次編號／受訪對象（部門＋角色）／場次目的一句話／時長／涵蓋模組／排序理由備註。客戶已有安排時改為「對應與微調建議表」。

**產出物 B｜各場訪綱**：依 01 骨架每場一份；文件標題照 01 規則；文末附本場資料索取清單；被自動刪減的題目列於附註（見 05）。「給主訪的備註」隨對話提供並另產 md 檔集中維護，不寫入訪綱本體；寫回 Notion 時建為訪綱目錄頁下的第一頁（排在各場訪綱之前）。

**產出物 C｜必問題對照表**：使用者有提供必問清單時，標明每題放進哪一場哪一段。

品質標準：場次規劃合理不需重拆／題目可直接照唸、用詞中性專業／題量符合時長／不需大改即可送客戶窗口確認。
