# 訪談題目設計原則（獨立檢核版）

此檔為題庫與訪綱產出的**唯一基準**。任何批次產出前必讀本檔；產出後必須執行第二節的逐題檢核，通過才能交付。

---

## 一、13 條題目設計原則

1. **一題一焦點**：一題只問一個面向，其他面向放追問，不寫複合題。
2. **提問層次對齊受訪者**：不設計「要受訪者當場濃縮出 KPI／目標」的題目。對一般受訪者，題目落在工作第一層看得到、不需額外思考彙整的現象與觀察；若上層有給定指標或內部已訂目標，可直接問「有沒有收到相關指示／內部有沒有訂目標」蒐集既有事實，並延伸了解該層級的認知。「自行歸納目標／策略」的題保留給主管／決策者場。
3. **以實例提問**：優先用「以最近一次⋯為例」「可以舉個例子嗎」開頭，讓受訪者用日常觀察回答。
4. **不過度引導、想問什麼就直接問**：舉例引導最多一組、放在追問裡，不寫進主題目；不用「大範圍問題＋括號舉例」代替明確提問——想問特定面向（如有沒有固定檔期節奏）就直接問那個面向。
5. **先合併再收錄**：同用途題合併成「一個主題目＋分層追問」；過去訪綱問法非 100% 照搬。
6. **索取句掛題＋收尾彙整**：資料索取不獨立成題，掛在對應需求題後；索取項來源＝訪綱預列＋訪談中提到，收尾可安排彙整提醒。
7. **迴避組織張力類問題**：不直接問部門間的衝突、對立、抱怨、反對（如「合作最痛的點」「誰會反對」）；改中性問法間接了解、由主訪感知、或私下問窗口。收尾補問用「補充建議」語氣。
8. **段落標題受訪者可讀**：段落標題用白話名詞短語，不用術語；整份文件一套標題，訪談雙方看同一份。
9. **開放式結尾**：題目不停在「是／否」判斷；先確認事實後接開放延伸。
10. **不預設立場**：題目與追問不預設受訪者的情境、職責或狀態（例：不預設他手邊在忙、不預設部門要做檢查、不預設想要更多資料、不預設客服有教學職責且遇到困難）。要確認特定情境用中性問法讓受訪者自己描述。若問的是普遍常見、多數公司都會做的事，用「有沒有哪些⋯」開頭最保險——既不預設對方一定有做、也不顯得意外對方有做。
11. **肯定語氣**：陳述已知資訊用確定語（「我們有接收到⋯的訊息」），不用「聽說」「好像」。
12. **顆粒度與追問節制**：主題目顆粒度不切太細，先蒐集初步回覆、視內容自然追問；每題追問提示以一則為原則。
13. **期待先開放再收斂**：先開放蒐集多個期待，再用「只能先做一件」收斂，兩題成對。
14. **任務目的先於工具介面**：對內工具案的訪綱要能同時收到「背後任務的目的與缺口」與「工具使用的具體痛點」——先問使用者要完成的任務本身怎麼進行、哪裡最花力氣、工具幫上與幫不上的部分，再進工具操作細節。只圍繞既有工具的使用問題會讓改版淪為介面優化，看不到根本性的效率價值缺口。
15. **段內題序由大到小**：同一段落內的題目，從大範圍、方向性的問起，逐漸收到小而具體的題目。
16. **段落依思維層次分群**：整份訪綱的段落排序，把需要思考的主題（策略、觀察、看法類）相鄰排在前面，日常操作、行為描述、具體規範限制類的主題排在後面——先問完要動腦歸納的，再問直覺可答的，讓訪談雙方不必反覆切換思考模式。必要時可為此合併段落、或把特定題目併到其他段落。

## 二、產出前逐題檢核程序（固定工作流）

每一題交付前依序自問：

- [ ] 這題是不是只問一個焦點？追問是否只有一則？（原則 1、12）
- [ ] 受訪者用日常觀察就能回答，不需當場歸納？（原則 2、3）
- [ ] 有沒有預設受訪者的職責、情境、意願？（原則 10）——逐字檢查主詞與動詞隱含的前提
- [ ] 結尾是開放的，不是停在是／否？（原則 9）
- [ ] 有沒有組織張力字眼或框架？（原則 7）
- [ ] 語氣是肯定的？（原則 11）
- [ ] 佔位符 {X} 的內容，產綱時填得出來嗎？——**填不出來（需訪談中才知道）的，不得為固定題**，改為條件題並標注觸發來源（哪個輸入欄位提供），或刪除
- [ ] 這題的目的想清楚了嗎？——說不出「答案會影響什麼設計決策」的題，刪除

## 三、產題句式參考（引擎改寫用，不出現在使用者文件）

- **排序句式**：「如果要排這些的先後順序，您會怎麼排？為什麼？」／「請按 {頻繁程度／重要程度} 排一下這些項目：{清單}」（條件：主訪已備妥清單）
- **成功定義兩段式**：「期待之後有什麼具體的改變？」→「會怎麼判斷有沒有達到？」（先開放、再問檢核方式，不預設指標）
- **實例句式**：「以最近一次⋯為例」「可以舉個例子嗎」
- **保留句式**：「現在的 {產品}，有沒有做得不錯、應該保留的地方？」
- **有沒有句式**：問普遍常見的做法時用「有沒有哪些⋯」開頭（原則 10）
- **控場註記句式**：「本段先聚焦最重要的 1–2 項，剩餘時間再談其他。」

## 四、條件題標注規範

條件題必須寫明觸發來源，格式：「（條件題：{輸入欄位／狀況} 時使用）」。
合法觸發來源＝規格 v2 §1 的輸入欄位：業務前期筆記、設計師走查觀察／商店評價、利關人結構與執掌、開放題（特別注意事項）、既有場次安排、必問清單。
訪談中才會出現的資訊（如「關鍵卡住步驟」）不能當觸發來源——那是現場追問的職責，不進訪綱。
